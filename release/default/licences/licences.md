### Notices in the linked sources

COPYRIGHT.rst says: "Where source code headers specify Copyright & License information, this information takes precedence over the summaries made here." So the header of every source an image links is read too -- from ESP-IDF and from its managed components, found through the build's compile_commands.json, which names the object each source became, and counted as linked as a component is, by a global symbol the object defines being defined in the image. A header that is Espressif's alone under Apache-2.0 asks nothing beyond ESP-IDF's LICENSE, and is passed over. Any other notice goes with the image: a header that holds its licence terms is carried once per distinct text, with every linked source it heads; a header that names its holders and only names its licence, or points at a file, is matched to the licence file nearest it in its component that meets every part of its SPDX expression, else to the COPYRIGHT.rst entry covering it; one that names only BSD-3-Clause, or only the FreeBSD License (BSD-2-Clause-FreeBSD), gets SPDX's BSD-3-Clause or BSD-2-Clause-Views text with its holder lines, said so beside it; any other is carried and flagged.

**What this cannot see.** An object whose code reached the image with no global symbol of its own -- a static function inlined into another object, a table reached only through a pointer -- does not count as linked, so its header is not read. A notice written below a source's first line of code is not read. A prebuilt library has no source to read, and is matched below by its archive. The project's own sources, and garden's, are under the project's licence.
